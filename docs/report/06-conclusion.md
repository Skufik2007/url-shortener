# Заключение

В ходе курсовой работы разработан и реализован веб-сервис сокращения ссылок с аналитикой переходов на стеке Go, PostgreSQL и Redis. Сервис развёртывается одной командой Docker Compose, не зависит от сторонних облачных платформ и хранит данные на инфраструктуре владельца. Результаты по задачам, поставленным во введении, состоят в следующем.

1. **Предметная область и аналоги.** Исследован принцип работы сервисов сокращения ссылок, выбрано временное перенаправление 302 с запретом кэширования (`Cache-Control: private, max-age=0`), которое обеспечивает учёт каждого перехода и возможность отключения ссылки. Рассмотрены семь аналогов; установлено, что коммерческие решения закрыты и хранят данные у третьей стороны, а открытые используют иные стеки (глава 1).
2. **Генерация кодов.** Проанализированы способы генерации и оценена ёмкость пространства кодов. Выбран случайный код base62 длиной 7 символов на `crypto/rand` с отсечением смещённых значений: ёмкость составляет около 3,5·10^12, вероятность коллизии при вставке в таблицу из 10^7 записей — около 2,8·10^(−6), уникальность гарантируется ограничением `UNIQUE` и повторной генерацией (до пяти попыток).
3. **Требования.** Сформулированы 11 функциональных и 8 нефункциональных требований, выполнен анализ угроз по классификации OWASP. В реализации обеспечены ограничение частоты регистрации, входа и создания ссылок, подпись токенов HMAC-SHA256 с постоянным временем сравнения, bcrypt со стоимостью 12, параметризованные SQL-запросы, вывод в дашборде средствами DOM и строгая политика CSP.
4. **Архитектура и проектирование.** Спроектирована слоистая архитектура с интерфейсами хранилища, кэша и сборщика аналитики, построены диаграммы контейнеров, вариантов использования, последовательности, классов, ER-диаграмма и диаграмма развёртывания; определён REST API (глава 2).
5. **Аналитика без замедления редиректа и обезличивание.** Реализован асинхронный конвейер: обработчик помещает событие в буферизованный канал неблокирующей отправкой, пул воркеров пакетно записывает переходы командой `COPY`, при остановке очередь дренируется. Реализовано обезличивание: IP-адрес не сохраняется, уникальные посетители определяются по усечённому SHA-256 от соли, IP и User-Agent, реферер сводится к домену.
6. **Технологии, контейнеризация и CI.** Обоснован выбор Go, PostgreSQL, Redis, pgx и go-redis, собственных HMAC-токенов. Подготовлены многоэтапный образ на основе `distroless`, Compose с проверками работоспособности и конвейер GitHub Actions из пяти заданий (тесты с детектором гонок, интеграционные тесты, линтер, `gosec` и `govulncheck`, сборка образа).
7. **Реализация и проверка.** Сервис реализован и покрыт тестами: 71 функция тестов (169 с подтестами) проходит успешно, покрытие пакетов с модульными тестами — от 81,5 до 100 % (91,5 % суммарно), хранилище PostgreSQL проверяется интеграционными тестами в CI. Тесты выявили три дефекта, все исправлены. Статический анализ `go vet` замечаний не дал; `govulncheck` нашёл 13 уязвимостей стандартной библиотеки go1.27.1, устранённых фиксацией инструментальной цепочки go1.27.2.

**Достигнутые показатели.** Разрешение закэшированной ссылки в сервисном слое занимает около 58 нс (одна аллокация); обработка редиректа в HTTP-слое — около 10 мкс без сети. В демонстрационном режиме при нагрузке с той же машины сервис обработал около 5,6 тыс. редиректов в секунду без ошибок транспорта; при 64 одновременных запросах 99-й процентиль задержки составил 14,9 мс, при 256 — 55,7 мс, потерянных событий аналитики не зафиксировано. Эти значения получены в одной конфигурации (клиент и сервер на одной машине, хранилище и кэш в памяти) и являются оценкой снизу; замеры с PostgreSQL и Redis, а также сценарием k6 не проводились.

**Ограничения.** Состояние ограничителя частоты хранится в памяти процесса; редиректы не лимитируются на уровне приложения; токен не отзывается до истечения срока действия; рейтинг популярных ссылок приближённый; при сбое записи пакета аналитики его данные теряются; сервис не проверяет адреса по базам вредоносных ресурсов.

**Перспективы развития.**

- Генерация QR-кодов для коротких адресов, в том числе для печатной продукции.
- Пользовательские домены для брендированных ссылок.
- Кластер Redis (Redis Cluster или Sentinel) для отказоустойчивости кэша и общего состояния ограничителя частоты.
- Перенос аналитики в колоночное хранилище (ClickHouse) и предварительная агрегация; секционирование таблицы `clicks` по времени в PostgreSQL.
- Аутентификация через OAuth/OpenID Connect и механизм отзыва токенов.
- Экспорт метрик в Prometheus и построение панелей в Grafana; трассировка запросов.
- Ограничение частоты редиректов по IP и по коду ссылки.
- CAPTCHA при регистрации и интеграция проверки адресов по базам фишинговых ресурсов.
- Профилирование и тестирование производительности с реальными PostgreSQL и Redis, буферизация журнала доступа.
